# Yaqin Gastro Cafe — сайт и кабинет управления

Дата: 2026-10-14
Статус: черновик на согласовании

## 1. Цель

Сделать сайт кафе Yaqin Gastro Cafe (NRG U-Tower, Ташкент) по готовому дизайну
и кабинет, в котором владелец сам ведёт меню и содержимое главной страницы.

Гости и владелец пользуются сайтом в основном с телефона: гость открывает меню по
QR-коду со стола, владелец правит меню и фото со своего смартфона. Поэтому и сайт,
и кабинет проектируются в первую очередь под телефон.

**Критерии успеха**

- Главная и меню выглядят как в макете на телефоне и на компьютере, на трёх языках (UZ / RU / EN).
- Владелец с телефона добавляет, меняет, скрывает, сортирует и удаляет категории и блюда,
  в том числе фотографирует блюдо камерой и сразу загружает фото.
- Владелец с телефона меняет тексты и фото главной страницы и контакты.
- Правки видны на сайте сразу после сохранения.
- Всё запускается одной командой `docker compose up -d` на VPS.

## 2. Объём

**Входит**

- Публичный сайт: главная и меню, три языка.
- Кабинет `/admin`: категории, блюда, содержимое главной, смена пароля.
- Бэкенд на Node.js, база SQLite, хранение и обработка фото.
- Docker-развёртывание, бэкап, восстановление пароля из командной строки.

**Не входит**

- Корзина, приём заказов и оплата на сайте. Заказ — через Telegram или звонок, как в макете.
- Опции блюд (прожарка, размер, добавки).
- Несколько пользователей и роли — один администратор.
- Генерация QR-кода, аналитика, офлайн-режим, метки «Популярное» и подобные.
- Редактирование подписей интерфейса (навигация, кнопки, надзаголовки) — они в коде.

## 4. Архитектура

Одно приложение на Fastify отдаёт и сайт, и кабинет. HTML собирается на сервере
шаблонами Eta, на клиенте — небольшой JS без сборки.

**Стек**

| Задача | Решение |
|---|---|
| Сервер | Node.js 22, Fastify 5 |
| Шаблоны | Eta через `@fastify/view`, авто-экранирование включено |
| База | SQLite через `better-sqlite3` (WAL, `foreign_keys = ON`) |
| Фото | `sharp` → WebP |
| Формы | `@fastify/formbody`, `@fastify/multipart` |
| Сессии и защита | `@fastify/cookie`, `@fastify/csrf-protection`, `@fastify/rate-limit`, `@fastify/helmet` |
| Статика | `@fastify/static` |
| Сортировка в кабинете | SortableJS, файл лежит в `public/vendor/` |
| Тесты | `node:test` + `fastify.inject` |

**Структура проекта**


**Поток запроса**

- Сайт: маршрут → repos (синхронные запросы к SQLite) → шаблон → HTML. Кэша нет:
  чтение из SQLite занимает доли миллисекунды, правки видны сразу.
- Кабинет: форма POST → проверка данных → repos → редирект (Post/Redirect/Get).
  Быстрые действия (видимость, порядок) — `fetch` к JSON-маршрутам `/admin/api/*`.

**Границы модулей**

- `repos/*` знают только SQL и не знают про HTTP.
- `services/images.js` знает только файлы и `sharp`, не знает про базу.
- Маршруты связывают repos и services, проверяют данные и выбирают шаблон.
- `content-schema.js` — единственное место, где перечислены поля главной; форма кабинета,
  проверка данных и значения по умолчанию строятся по нему.

## 5. Модель данных

`db/migrations/001_init.sql`. Номер применённой миграции хранится в `PRAGMA user_version`;
при старте применяются все миграции с номером больше текущего.

```sql
CREATE TABLE categories (
  id          INTEGER PRIMARY KEY,
  slug        TEXT    NOT NULL UNIQUE,          -- a-z0-9-, якорь #cat-<slug>
  name_ru     TEXT    NOT NULL,
  name_uz     TEXT    NOT NULL DEFAULT '',
  name_en     TEXT    NOT NULL DEFAULT '',
  sort_order  INTEGER NOT NULL,
  is_visible  INTEGER NOT NULL DEFAULT 1,
  created_at  TEXT    NOT NULL DEFAULT (datetime('now')),
  updated_at  TEXT    NOT NULL DEFAULT (datetime('now'))
);

CREATE TABLE dishes (
  id          INTEGER PRIMARY KEY,
  category_id INTEGER NOT NULL REFERENCES categories(id) ON DELETE RESTRICT,
  name_ru     TEXT    NOT NULL,
  name_uz     TEXT    NOT NULL DEFAULT '',
  name_en     TEXT    NOT NULL DEFAULT '',
  desc_ru     TEXT    NOT NULL DEFAULT '',
  desc_uz     TEXT    NOT NULL DEFAULT '',
  desc_en     TEXT    NOT NULL DEFAULT '',
  amount      INTEGER,                          -- NULL: вес/объём не показывать
  unit        TEXT    CHECK (unit IN ('g', 'ml', 'pcs')),
  price       INTEGER NOT NULL,                 -- в сумах
  image       TEXT,                             -- id фото или NULL
  sort_order  INTEGER NOT NULL,
  is_visible  INTEGER NOT NULL DEFAULT 1,
  created_at  TEXT    NOT NULL DEFAULT (datetime('now')),
  updated_at  TEXT    NOT NULL DEFAULT (datetime('now'))
);
CREATE INDEX dishes_category ON dishes(category_id, sort_order);

CREATE TABLE content (
  key         TEXT PRIMARY KEY,                 -- ключ из content-schema.js
  value       TEXT NOT NULL,                    -- JSON
  updated_at  TEXT NOT NULL DEFAULT (datetime('now'))
);

CREATE TABLE users (
  id            INTEGER PRIMARY KEY,
  login         TEXT NOT NULL UNIQUE,
  password_hash TEXT NOT NULL,                  -- scrypt: salt и хэш
  created_at    TEXT NOT NULL DEFAULT (datetime('now'))
);

CREATE TABLE sessions (
  id          TEXT PRIMARY KEY,                 -- 32 случайных байта, hex
  user_id     INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  expires_at  TEXT NOT NULL,
  created_at  TEXT NOT NULL DEFAULT (datetime('now'))
);
```

**Правила**

- `amount` и `unit` задаются вместе: оба пустые или оба заполнены.
- Новая категория или блюдо получает `sort_order = max + 1` (в конец списка).
  При переносе блюда в другую категорию оно встаёт в конец новой категории.
- Категорию, в которой есть блюда (в том числе скрытые), удалить нельзя.
  Кабинет показывает: «Сначала перенесите или удалите блюда этой категории».
- Удаление блюда удаляет и файлы его фото.
- Slug создаётся из `name_en`, а если его нет — из транслитерированного `name_ru`.
  При совпадении добавляется `-2`, `-3`. Slug можно поменять в форме категории.
- Сессия живёт 30 дней с момента входа. Просроченные сессии удаляются при старте сервера
  и при каждом входе.

## 6. Содержимое главной (`content-schema.js`)

Схема — массив групп, у группы — список полей. У поля есть: `key`, `type`
(`text` | `textarea` | `image` | `phone` | `username` | `plain`), `translatable`, подпись для
кабинета, ограничение длины и значение по умолчанию из макета.

Формат `value` в таблице `content`:

- переводимое поле — `{"ru": "...", "uz": "...", "en": "..."}`;
- непереводимое — строка;
- фото — `{"image": "<id>"}` или отсутствие записи (тогда используется значение по умолчанию).

| Группа | Ключ | Тип | Перевод | Где на сайте |
|---|---|---|---|---|
| Первый экран | `hero.floor` | text | да | строка над YAQIN |
| | `hero.tagline` | text | да | слоган, `<title>` главной |
| | `hero.description` | textarea | да | текст под слоганом, `meta description` |
| | `hero.image` | image | — | фон первого экрана, Open Graph; по умолчанию `hero-default.webp` |
| Часы и адрес | `info.hours` | text | да | «Ежедневно 08:00 – 23:00»: первый экран, «Как добраться», меню |
| | `info.hoursShort` | plain | нет | «08:00 – 23:00»: карточка в «Контактах» |
| | `info.addressShort` | text | да | «NRG U-Tower, 1 этаж»: первый экран |
| | `info.addressFull` | text | да | «NRG U-Tower, 1 этаж, Ташкент»: «Как добраться» |
| О нас | `about.title` | text | да | заголовок |
| | `about.p1`, `about.p2` | textarea | да | два абзаца |
| | `about.image` | image | — | фото слева |
| | `about.f1.title` … `about.f3.title` | text | да | заголовки трёх преимуществ |
| | `about.f1.text` … `about.f3.text` | text | да | тексты трёх преимуществ |
| Атмосфера | `gallery.title` | text | да | заголовок |
| | `gallery.description` | textarea | да | описание |
| | `gallery.image1` … `gallery.image4` | image | — | 4 фото сетки |
| Онлайн-заказ | `order.title` | text | да | заголовок |
| | `order.description` | textarea | да | описание |
| Контакты | `contacts.phone` | phone | нет | «+998 90 000 00 00»; ссылка `tel:` — только цифры и `+` |
| | `contacts.telegram` | username | нет | `yaqin_gastro` → `https://t.me/yaqin_gastro`, кнопка «Заказать в Telegram» |
| | `contacts.instagram` | username | нет | `yaqin.gastro` → `https://instagram.com/yaqin.gastro` |
| Как добраться | `location.title` | text | да | заголовок |
| | `location.mapQuery` | plain | нет | «NRG U-Tower, Tashkent»: ссылки Google и Яндекс Карт, встроенная карта |

Значения по умолчанию — тексты макета (`T` в `home.dc.html`).

Проверка значений:

- `text` и `plain` — до 200 символов, `textarea` — до 1000. Русский вариант переводимого поля
  обязателен, узбекский и английский можно оставить пустыми.
- `phone` — `^\+?[0-9 ()-]{7,20}$`.
- `username` принимает `@name`, `name` или ссылку и сохраняет только `name`
  (`^[A-Za-z0-9._]{1,32}$`).

**Подписи интерфейса** (`src/i18n/ui.js`, не редактируются в кабинете): пункты навигации,
надзаголовки секций («О нас», «Атмосфера», «Контакты»…), подписи кнопок («Смотреть меню»,
«Заказать онлайн», «Заказать в Telegram», «Позвонить»), подписи «Часы работы» / «Адрес»,
подписи и подсказки карточек контактов, «Яндекс Карты», тексты страницы меню («Меню»,
«Цены указаны в сумах»), валюта (сум / so’m / UZS), единицы (г / g / g, мл / ml / ml,
шт / dona / pcs), тексты страниц 404 и 500.

## 7. Публичный сайт

### 7.1. Маршруты

| Маршрут | Что делает |
|---|---|
| `GET /` | 302 на `/{lang}`: язык из cookie `lang`, иначе `ru` |
| `GET /:lang` | Главная. `lang` ∈ `ru`, `uz`, `en`, иначе 404 |
| `GET /:lang/menu` | Меню |
| `GET /static/*` | `public/`, кэш 7 дней |
| `GET /uploads/*` | `data/uploads/`, кэш 1 год, `immutable` (имена файлов уникальны) |
| `GET /robots.txt` | Разрешает всё, кроме `/admin`, ссылка на sitemap |
| `GET /sitemap.xml` | 6 адресов: главная и меню на трёх языках |

### 7.2. Языки

- Язык задаётся адресом. Каждая отрисованная страница записывает его в cookie `lang`
  (1 год, `SameSite=Lax`).
- Переключатель UZ | RU | EN — ссылки на ту же страницу на другом языке.
- `tr(field, lang)` возвращает значение на нужном языке, а если оно пустое — на русском.
- `<html lang>`: `ru`, `uz`, `en`. В `<head>` — `hreflang`-ссылки на все три версии
  и `x-default` на русскую. Абсолютные адреса строятся от `PUBLIC_URL`.

### 7.3. Главная

Секции по макету: шапка, первый экран 1a, «О нас», «Атмосфера», «Онлайн-заказ», «Контакты»,
«Как добраться», футер. Данные — из `content` и `ui.js`.

- Первый экран: `min-height: max(620px, calc(100svh - 72px))`, чтобы высота не прыгала,
  когда мобильный браузер прячет адресную строку.
- Галерея: сетка 4 колонки × строки 260 px на широких экранах, 2 колонки × 170 px на узких,
  с теми же объединениями ячеек, что в макете.
- Фото, которого нет в базе: у первого экрана — `hero-default.webp`, у остальных —
  фирменная заглушка (фон `#1E4232`, монограмма YAQIN цветом `#C9A96E`).
- Карта — `iframe` Google Maps по `location.mapQuery`, `loading="lazy"`.
- Год в футере — текущий.

### 7.4. Меню

- Вступление: заголовок «Меню», часы работы, примечание о валюте.
- Прилипающая полоса вкладок под шапкой (`top: 72px`), прокручивается по горизонтали.
  Нажатие — плавная прокрутка к категории с учётом высоты шапки и вкладок. При прокрутке
  страницы активная вкладка подсвечивается и центрируется в полосе (логика `spy()`
  и `centerTab()` из макета). Без JS вкладки — обычные якорные ссылки `#cat-<slug>`.
- Показываются только видимые категории, в которых есть хотя бы одно видимое блюдо.
  Порядок — по `sort_order`.
- Цена форматируется с неразрывным пробелом между тысячами: `95 000 сум`.
- Блюдо без фото — фирменная заглушка.

**Ширина ≥ 600 px** — карточки как в макете: сетка `repeat(auto-fill, minmax(264px, 1fr))`,
фото 4:3, название, описание, вес/объём и цена. Карточки не нажимаются — вся информация
уже на них.

**Ширина < 600 px** — сетка в 2 колонки: фото 4:3, название (до 2 строк), вес/объём, цена.
Описание в сетке не показывается. Нажатие на карточку открывает нижнюю карточку блюда:

- `<dialog>`, выезжает снизу: ручка, кнопка ✕, большое фото, название, описание,
  вес/объём, цена;
- данные берутся из разметки самой карточки, запроса к серверу нет;
- при открытии в историю добавляется запись `#dish-<id>`, поэтому кнопка «Назад»
  на телефоне закрывает карточку, а не уводит со страницы;
- закрывается свайпом вниз (больше 80 px), нажатием на фон, кнопкой ✕, `Esc`, «Назад».

### 7.5. Скорость и доступность

- Шрифты лежат на нашем сервере (woff2, только используемые начертания, latin + cyrillic),
  `font-display: swap`, основные начертания подгружаются через `preload`.
- Фото — WebP через `srcset` и `sizes`. Всё ниже первого экрана — `loading="lazy"`.
  Фото первого экрана — `fetchpriority="high"`.
- Свой JS: `site.js` (бургер) и `menu.js` (вкладки, карточка блюда). Цель — не больше 10 КБ
  вместе, без библиотек.
- Кнопки и ссылки — не ниже 44 px. Видимый фокус. `alt` у фото блюд — название блюда.
  Кнопки без текста подписаны через `aria-label`.

### 7.6. Мета-данные

- `<title>`: главная — `YAQIN Gastro Cafe — {hero.tagline}`, меню — `{Меню} — YAQIN Gastro Cafe`.
- `meta description` — `hero.description`.
- Open Graph: заголовок, описание, фото первого экрана (1200 px).
- `favicon.svg` с монограммой YAQIN.

## 8. Кабинет `/admin`

Интерфейс на русском, светлый (фон `#FBF7F0`, шапка `#0F241A`, акцент `#C9A96E`, Manrope).
Проектируется под телефон: одна колонка шириной до 720 px, на компьютере — по центру.

### 8.1. Каркас

- Шапка: «YAQIN · кабинет» и ссылка «Открыть сайт ↗».
- Нижняя панель навигации: **Меню · Главная · Аккаунт**. На экранах от 768 px та же
  навигация переезжает в шапку.
- Кнопка «Сохранить» в формах прилипает к низу экрана.
- После сохранения — уведомление «Сохранено» (редирект с `?saved=1`, уведомление исчезает
  через 3 секунды).
- Все страницы кабинета, кроме входа, требуют сессию. Без сессии — редирект
  на `/admin/login?next=<адрес>`.
- `admin.webmanifest`: `name` «Yaqin — кабинет», `start_url` `/admin`, `display: standalone`,
  `theme_color` `#0F241A`, иконки 192 и 512 px. Кабинет можно добавить на экран «Домой».
  Офлайн-режима нет.

### 8.2. Маршруты

| Маршрут | Что делает |
|---|---|
| `GET /admin/login`, `POST /admin/login` | Вход |
| `POST /admin/logout` | Выход, удаляет сессию |
| `GET /admin` | Экран «Меню» |
| `GET /admin/categories/new`, `POST /admin/categories` | Создание категории |
| `GET /admin/categories/:id/edit`, `POST /admin/categories/:id` | Правка категории |
| `POST /admin/categories/:id/delete` | Удаление категории |
| `GET /admin/dishes/new?category=:id`, `POST /admin/dishes` | Создание блюда |
| `GET /admin/dishes/:id/edit`, `POST /admin/dishes/:id` | Правка блюда |
| `POST /admin/dishes/:id/delete` | Удаление блюда |
| `POST /admin/api/categories/order` | JSON `{ids: [...]}` — новый порядок категорий |
| `POST /admin/api/dishes/order` | JSON `{categoryId, ids: [...]}` — порядок блюд в категории |
| `POST /admin/api/categories/:id/visibility` | JSON `{visible: true|false}` |
| `POST /admin/api/dishes/:id/visibility` | JSON `{visible: true|false}` |
| `GET /admin/home` | Экран «Главная» |
| `POST /admin/home/:group` | Сохранение одной группы полей (multipart) |
| `GET /admin/account`, `POST /admin/account/password` | Смена пароля |

Маршруты порядка принимают только полный набор id этой категории или всех категорий;
иначе — 400, порядок не меняется.

### 8.3. Экран «Меню»

- Категории — раскрывающиеся блоки. Какие блоки раскрыты, запоминается в `localStorage`
  (ошибка доступа к хранилищу не ломает экран).
- Заголовок категории: ручка ≡, название (RU), число блюд, переключатель видимости,
  кнопка ✎ (правка категории).
- Строка блюда: ручка ≡, миниатюра 48 px, название (RU) и цена, переключатель видимости.
  Нажатие на строку — правка блюда.
- В конце каждой категории — «+ Блюдо», внизу экрана — «+ Категория».
- Перетаскивание только за ручку ≡ (SortableJS, `handle`), чтобы не мешать прокрутке пальцем.
  Порядок сохраняется сразу после отпускания. При ошибке — сообщение, и порядок
  на экране возвращается к прежнему.
- Переключатель видимости сохраняется сразу. При ошибке — сообщение, и переключатель
  возвращается в прежнее положение.
- Скрытые категории и блюда показаны приглушёнными.

### 8.4. Формы категории и блюда

- Вверху формы — переключатель **RU | UZ | EN**. Он показывает поля выбранного языка
  для всех переводимых полей сразу. На вкладке, где есть ошибка, — красная точка.
  Без JS все поля трёх языков показаны друг под другом.
- Категория: название (RU обязательно, до 60 символов), slug, «Показывать на сайте».
- Блюдо: категория (список), название (RU обязательно, до 120 символов), описание
  (до 500 символов), вес/объём (число + единица г / мл / шт, можно оставить пустым),
  цена (целое число от 0 до 100 000 000, цифровая клавиатура `inputmode="numeric"`),
  фото, «Показывать на сайте».
- Фото:
  - кнопка «Выбрать фото» — `<input type="file" accept="image/*">`, на телефоне
    открывает камеру или галерею;
  - перед отправкой `admin.js` уменьшает фото в браузере до 2000 px по длинной стороне
    (canvas → JPEG, качество 0.85) и показывает предпросмотр;
  - если браузер не смог открыть файл, отправляется оригинал;
  - у сохранённого фото — кнопка «Удалить фото».
- Внизу формы правки — красная кнопка «Удалить» с подтверждением.
- При ошибке форма открывается снова со всеми введёнными значениями и текстом ошибки
  у поля. Выбранное, но не сохранённое фото нужно выбрать заново — об этом говорит подсказка.

### 8.5. Экран «Главная»

- Форма строится по `content-schema.js`. Группы — раскрывающиеся блоки в порядке секций
  на сайте.
- Каждая группа — отдельная форма со своей кнопкой «Сохранить»: ошибка в одной группе
  не сбрасывает правки в других.
- Переводимые поля — с тем же переключателем RU | UZ | EN.
- У поля-фото видна текущая картинка, кнопки «Заменить» и «Вернуть по умолчанию».
  Уменьшение фото в браузере — как в 8.4.

### 8.6. Аккаунт

- Смена пароля: текущий пароль, новый (не короче 8 символов), повтор.
  После смены все остальные сессии удаляются.
- Кнопка «Выйти».

## 9. Фото

| Вид | Ширины WebP | Где используется |
|---|---|---|
| `dish` | 400, 800 | карточки, карточка блюда, миниатюры кабинета |
| `hero` | 1200, 2000 | первый экран, Open Graph |
| `about`, `gallery` | 800, 1400 | «О нас», галерея |

- `services/images.js`:
  - принимает поток файла (до 15 МБ);
  - проверяет, что `sharp` может его прочитать (иначе ошибка «Не удалось прочитать фото,
    сохраните его как JPEG или PNG»);
  - поворачивает по EXIF (`rotate()`), уменьшает до нужных ширин без увеличения,
    сохраняет WebP с качеством 80;
  - имя: `<вид>-<randomUUID>-<ширина>.webp` в `data/uploads/`, в базу пишется
    `<вид>-<randomUUID>`.
- Сначала записываются новые файлы, потом обновляется база, потом удаляются старые файлы.
  Если запись в базу не удалась — новые файлы удаляются. Если не удалось удалить старые —
  предупреждение в лог, запрос успешен.
- Шаблоны строят `srcset` по виду фото.

## 10. Безопасность

- Пароли: `crypto.scrypt` со случайной солью, сравнение через `timingSafeEqual`.
- Cookie сессии `sid`: подписанная, `httpOnly`, `SameSite=Lax`, `Secure` в продакшене,
  `path=/admin`.
- CSRF: токен в каждой форме кабинета и в заголовке `fetch`-запросов
  (`@fastify/csrf-protection`). Запрос без верного токена — 403.
- Вход: не больше 5 попыток в минуту с одного IP (`@fastify/rate-limit`), сообщение
  об ошибке не говорит, что именно неверно — логин или пароль.
- `next` после входа принимается только как путь внутри `/admin`.
- `@fastify/helmet` с CSP:
  `default-src 'self'; img-src 'self' data: blob:; frame-src https://www.google.com https://maps.google.com;
  script-src 'self'; style-src 'self'; font-src 'self'; form-action 'self'; frame-ancestors 'none'`.
  Поэтому в шаблонах нет inline-скриптов и inline-стилей.
- Все значения в шаблонах экранируются. Текст из кабинета выводится только как текст.
- Данные проверяются на сервере: типы, длины, диапазоны, допустимые значения `unit`,
  формат slug (`^[a-z0-9]+(-[a-z0-9]+)*$`), телефона и имени пользователя.
- Имена файлов фото придумывает сервер, путь из запроса к файловой системе не применяется.
- В продакшене без `SESSION_SECRET` сервер не стартует.

## 11. Ошибки

- Сайт: 404 и 500 — страницы в стиле сайта на языке из адреса (или русском).
  Стек ошибки — только в лог (pino), пользователю — нет.
- Кабинет: ошибки проверки — у полей; прочие ошибки — сообщение вверху формы с сохранением
  введённых значений. JSON-маршруты отвечают `{error: "..."}` с кодом 400/403/404/500.
- Попытка удалить непустую категорию — сообщение на странице правки категории, без удаления.
- Обращение к несуществующей категории или блюду в кабинете — 404 в стиле кабинета.

## 12. Тестирование

`node --test`, база — SQLite в памяти, папка фото — временная. Браузер не нужен.

- **repos:** создание, правка, порядок, видимость, запрет удаления непустой категории,
  перенос блюда в другую категорию, сессии и их срок.
- **services:** `images` на тестовой картинке (ширины, WebP, поворот по EXIF, отказ на «не
  картинке»), `auth` (хэш и проверка пароля), `slug` (транслитерация, уникальность),
  `i18n.tr` (фолбэк на русский).
- **маршруты сайта:** главная и меню отдаются на трёх языках; неизвестный язык — 404;
  `/` уходит на язык из cookie; скрытые блюда и категории без видимых блюд не видны;
  пустой перевод заменяется русским; контент из `content` попадает на страницу;
  экранирование `<script>` в названии блюда.
- **маршруты кабинета:** без сессии — редирект на вход; вход с неверным паролем — ошибка;
  лимит попыток; CRUD категорий и блюд; загрузка фото; порядок и видимость через API;
  сохранение группы главной; смена пароля удаляет другие сессии; запрос без CSRF-токена — 403.
- **ручная проверка перед сдачей:** сайт и кабинет в браузере на ширине 375 px и 1280 px —
  вкладки меню, карточка блюда и «Назад», загрузка фото, перетаскивание, переключение языков.

## 14. Развёртывание и эксплуатация

- **Первый запуск:** применяются миграции; если таблицы `categories` и `content` пусты —
  загружаются данные из макета (5 категорий, 24 блюда без фото, тексты главной);
  если `users` пуста — создаётся администратор из `ADMIN_LOGIN` / `ADMIN_PASSWORD`.
- **Docker:** `Dockerfile` на `node:22-slim`, `npm ci --omit=dev`, запуск от пользователя `node`.
  `docker-compose.yml`: один сервис, том `./data:/app/data`, порт `3000`, `env_file: .env`,
  `restart: unless-stopped`.
- **HTTPS:** обратный прокси на VPS. В репозитории — `Caddyfile.example`
  (`reverse_proxy localhost:3000`, сертификат Caddy выпускает сам).
- **Бэкап:** `npm run backup` (`docker compose exec app npm run backup`) кладёт копию базы
  в `data/backups/yaqin-<дата>.db`. Для полного бэкапа копируется папка `data/`.
- **Забытый пароль:** `docker compose exec app npm run set-password -- <логин>` запрашивает
  новый пароль и удаляет все сессии.
- **README:** запуск локально, запуск на VPS, Caddy, бэкап, сброс пароля.

## 15. Допущения

- Основной язык — русский: он обязателен в кабинете и используется как запасной на сайте.
- Галерея — ровно 4 фото, потому что сетка макета рассчитана на 4.
- Тексты страницы меню и подписи интерфейса правятся в коде (`src/i18n/ui.js`).
- Одновременная правка из двух мест не учитывается: администратор один, сохраняется
  последняя правка.
